Security, honestly

      

        
What does the server store?

        
Nothing. There is no database, no KV, no logs of link data. The entire link — salt, IV,
          ciphertext, unlock wrappers — travels inside the URL fragment. This page is a static file.

        
Can someone without the password read the destination?

        
No. The destination is AES-256-GCM encrypted. Without the password, passkey, or key file,
          it is indistinguishable from random bytes. With a quantum computer? Still no — AES-256 holds
          up; the real risk is weak passwords, which is why Argon2id and the passphrase
          generator exist.

        
Is my password sent to the server?

        
Never. Decryption happens in your browser. The password never leaves your device.

        
Then why the path-style option?

        
Fragments can be dropped by some chat apps or corporate filters. Path-style links put the
          ciphertext in the path, so the server does see it — but still cannot decrypt it.
          The password still never travels.

        
Where do links leak?

        
Browser history and cloud sync services store full URLs including fragments. If you use
          embedded-password links, the link is the credential — treat it like a password.
          Share strong links only over channels you trust.

        
What if the password is wrong?

        
The GCM authentication tag fails and decryption refuses — there is no way to tell a
          “close” password from a wrong one, and no server to rate-limit guesses, so use long
          passphrases.

        
Is the time-lock real?

        
It is a genuine sequential hash grind (can't be parallelized), but a determined opener
          can patch this page's JavaScript to skip the wait. It's a fair-use lock, not tamper-proof.

        
Can a link be revoked?

        
Stateless links can't be killed — only passwords can stop being shared. The optional
          premium mode stores only ciphertext server-side and adds burn-after-read, expiry
          enforcement, and fetch counters. See docs/PREMIUM.md.

        
What's “quantum secure” here?

        
Encryption: AES-256 (NIST post-quantum adequate). Keypairs: hybrid X25519 + ML-KEM-768 —
          needs both a classical and a quantum break. Signatures: Ed25519 + ML-DSA-65.
          Passwords: Argon2id memory-hardness. The weak link is always the human one.
